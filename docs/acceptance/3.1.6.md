# 3.1.6 acceptance

The background request failure was reproduced in Chrome: account lookup succeeded, then the separate profile-count endpoint returned HTTP 429 with an HTML body. Version 3.1.5 masked that status as an unreadable JSON response. No further live requests or account mutations were performed after the rate limit.

- 391 tests cover exact open-profile totals, rounded labels with exact tooltips, unrelated or conflicting counters, changing totals, missing profile context, HTML rate limits, login/challenge redirects, and cancellation of stalled response bodies.
- The large background fixture reads 2,104 followers in 43 pages and 101 following in three pages. It makes no profile-count request and opens no list dialog.
- Chromium acceptance runs the production primary button and fetch/JSON transport in both the extension and generated userscript. Synthetic responses are served by an isolated protocol handler, never Instagram. Both interfaces preserve the comparison after a subsequent HTML 429 and make no retry or fallback request.
- Release requires the exact main commit to pass the full suite, 45 overlay states, 11 PWA states, Chrome pairing, Windows/macOS packaging, archive inspection, and checksum verification.
- Existing visual thresholds remain unchanged. Historical screenshot capture provenance is retained.

The repaired build has not completed an authenticated comparison after the observed rate limit. Fixture success is not proof of current Instagram availability or complete server responses. Human screen-reader acceptance and Firefox live behavior remain unverified. Windows is unsigned; macOS packages are ad-hoc signed and not notarized.
