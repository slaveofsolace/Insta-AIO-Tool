# 3.1.7 acceptance

Current Instagram profile counters use hash links in a profile header whose heading names the exact account. Version 3.1.6 required list-path links, so those counters were ignored and the profile-count request was still sent. The fixture has been corrected to reproduce the hash-link markup.

The test matrix contains 480 tests plus the existing extension/userscript, Chrome pairing, 45-state overlay, 11-state PWA, and desktop package checks. Unscoped hash links and a different profile heading cannot supply authoritative totals.

The first authenticated background run with the hash-link fix reached both terminal pages without HTTP errors or profile-count requests. Both unique-account totals remained below the exact profile counters, so the comparison was correctly withheld. The response pages included a duplicate Following entry and a separate deactivated-account group. Neither explains the full discrepancy by itself.

Read-only inspection of Instagram's own dialogs showed 12-row requests: Followers sends `count`, `search_surface`, and a continuation cursor; Following sends `count` and a continuation cursor. A second installed candidate matched those parameters. It returned exactly the same incomplete unique totals with no HTTP errors, increasing requests from 117 to 247. Both terminal responses had `has_more: false`, no continuation cursor, and `should_limit_list_of_followers: false`. Following included one duplicate row. The 12-row experiment was reverted; it increased the cost without restoring any missing accounts.

Those runs inspected the primary `users` arrays, not every account-bearing response field. Subsequent inspection of Instagram's loaded list client found that its reducer also appends `self_deactivated_followers.facepile`. A read-only comparison confirmed that accounts present in that field were missing from the saved partial capture. This is a parser omission; the earlier checks did not establish that every returned account was retained. Its contribution to the full count discrepancy still requires a corrected authenticated run.

The parser now includes that exact follower group before identity deduplication. Unrelated groups, category counts, and Following responses cannot add follower-group records. Malformed or conflicting group identities stop the check. No missing accounts are fabricated and no total is forced to match.

Offline regression cases also exposed two independent identity errors: numeric JSON IDs could merge distinct accounts despite available exact text IDs, and a rename between the two lists could produce false non-mutuals. The parser now checks exact ID aliases, rejects unresolved numeric precision loss, and reconciles both lists by ID before returning the existing username-based row schema. Conflicting cross-list identities stop the comparison. These changes do not explain or resolve the recorded server-response gap.

Fresh assembly, all 468 tests, generated userscript parity, and extension/userscript browser fixtures pass after the group-parser and temporary-server recovery changes. The fixtures include the production background comparison buttons, incomplete-result handling, responsive layouts, and no-click boundaries. Retry tests cover server waits, elapsed deadlines, Stop, and security responses; group tests cover missing rows, duplicates, conflicting identities, and incomplete totals.

The corrected installed background reader also reached terminal responses without HTTP errors but remained short of the exact profile totals. Including deactivated-account records did not resolve the full discrepancy.

The primary button now uses guided native-dialog capture. Fresh verification passes assembly, repository hygiene, all 478 tests, the extension/userscript Chromium acceptance suite, and all 45 Windows overlay states. Changed screenshots were reviewed and regenerated without changing tolerances. Each surface collects 45 accounts per list while only seven rows are mounted, opens and closes the two dialogs in order, issues no direct API requests, and preserves the previous comparison after interruption. Unit cases also cover delayed rows, replaced scrollers, count mismatch, Stop, profile changes, closed dialogs, ambiguous controls, and rate-limit interruption. The browser suite retains responsive, 200%-zoom, keyboard, pairing, and action-driver fixture checks.

An installed-build hash check confirmed the guided candidate before a live profile scan. Native Followers navigation and accumulation worked, but the scan was stopped because the collector waited up to six seconds after each scroll for an offscreen next-page spinner. Native request timings were short relative to those waits. Stop returned the UI to idle and preserved the saved comparison; Following and final completeness were not tested in that run.

The collector now waits for a loading indicator only when it intersects the list viewport. Two regression cases cover offscreen spinners and visible pending loads; all 480 tests pass. Authenticated complete-comparison acceptance of the repaired guided flow has not passed. Keep this patch in draft until that gate is resolved. No live account mutations are part of this acceptance. Fixture evidence alone is insufficient.
