# 3.1.7 acceptance

Current Instagram profile counters use hash links in a profile header whose heading names the exact account. Version 3.1.6 required list-path links, so those counters were ignored and the profile-count request was still sent. The fixture has been corrected to reproduce the hash-link markup.

The test matrix contains 393 tests plus the existing extension/userscript, Chrome pairing, 45-state overlay, 11-state PWA, and desktop package checks. Unscoped hash links and a different profile heading cannot supply authoritative totals.

The first authenticated background run with the hash-link fix reached both terminal pages without HTTP errors or profile-count requests. Both unique-account totals remained below the exact profile counters, so the comparison was correctly withheld. The response pages included a duplicate Following entry and a separate deactivated-account group. Neither explains the full discrepancy by itself.

Read-only inspection of Instagram's own dialogs showed 12-row requests: Followers sends `count`, `search_surface`, and a continuation cursor; Following sends `count` and a continuation cursor. The checker now uses those observed parameters instead of requesting 50 rows with additional grouping/search options. This alignment is not yet proof that Instagram will return complete lists.

An authenticated comparison with the updated branch userscript must finish before this patch is promoted. No live account mutations are part of this acceptance. Fixture evidence alone is insufficient.
