# 3.1.10 acceptance

This patch corrects profile-counter detection for Instagram's non-navigation `#` links. The count reader requires a unique, visible profile header matching the current profile. The existing cursor traversal, cooldowns, and action engines are unchanged.

## Checks

- Assembly, 412/412 tests, generated-userscript parity, and extension/web archive checks passed locally.
- 45/45 overlay and 11/11 PWA screenshot states passed without replacing screenshots or widening tolerances. Baseline capture provenance is retained.
- Regression tests cover exact text and title counts, a 1,001-follower traversal, missing or mismatched headers, duplicate headers, unrelated links, rounded or malformed counts, hidden/dialog counters, conflicts, and changed totals.
- Production-button Chromium fixtures exercise the `#` layout in both extension and generated userscript, with no profile-metadata request or list-dialog click. The fixtures also check cooldown retry and Stop.
- Release promotion requires the exact main revision's complete CI matrix, visual checks, Windows/macOS package lifecycle checks, archive checks, and checksums.

## Limits

The profile layout was inspected read-only in Chrome. It contained exact counters on `#` links inside a profile header. Existing console evidence showed HTTP 429 for profile metadata. No request was repeated to bypass that restriction.

Automated fixtures do not prove a successful authenticated full-list comparison. Instagram can still rate-limit or omit relationships. Human screen-reader acceptance and Firefox live behavior remain unverified. No account mutations were performed.

Windows is unsigned. macOS packages are ad-hoc signed and not notarized.
