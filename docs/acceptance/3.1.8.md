# 3.1.8 acceptance

Instagram's native Followers request was observed redirecting to the homepage and returning HTML instead of relationship JSON. The cause of that redirect is unknown; it is not a proven rate-limit response. The native list also recycles rendered rows, so one scroll sweep can miss accounts even after reaching the bottom.

Version 3.1.8 keeps the guided Followers, close, Following, close sequence and uses Instagram's native list requests throughout. If a sweep ends short, the checker revisits that dialog with tighter overlapping scroll steps while retaining unique observed usernames. It accepts a list only when the unique count equals the unchanged exact profile total. Changed totals, conflicts, challenges, rate limits, and incomplete lists remain partial.

The earlier background-reader checkpoint passed assembly, generated-userscript parity, repository hygiene, all 505 tests, extension and userscript Chromium acceptance, Chrome pairing, all 45 reviewed Windows overlay states, and all 11 reviewed Windows PWA states. Native-button fixtures wait for delayed initial rows, handle a hidden indicator before a visible loader, collect 45 recycled rows per list while excluding 30 recommendations, and preserve the saved comparison when a native list is unavailable or its loader stalls. Background-button fixtures cover both cursor chains, partial-save preservation, restriction stops, and zero native-list clicks. Screenshot tolerances are unchanged.

Focused regressions cover a dialog mounted before its rows or scroller, a loading indicator that clears on the final wait, bounded initial-load and pagination-loader timeouts, Stop during either wait, rate-limit detection while waiting, and persistent resweep progress. These tests establish reader behavior, not recovery of Instagram's missing native data.

The installed candidate was verified against its source SHA-256 before authenticated testing. The full comparison failed: Instagram's native Followers request returned an HTTP 302 redirect to the homepage, followed by HTML instead of relationship JSON. That run exposed a capture defect: recommendations were counted as followers. The corrected reader excludes links after the recommendation heading and rejects an empty native list when the profile total is positive.
