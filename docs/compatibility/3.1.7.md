# 3.1.7 compatibility

Open your profile and select **Check Followers + Following**. The checker opens Followers, collects its rows, closes it, then repeats with Following. Please leave this tab open and untouched while it runs. **Stop** cancels the check.

The guided scan requires exact totals from the matching profile header, including Instagram's hash-link counters and exact numeric tooltips. It retains accounts across recycled DOM windows and reacquires replaced scrollers. Missing totals or ambiguous navigation controls stop before opening a list. This flow does not call the background API reader.

Profile changes, manual page interaction, closed or unexpected dialogs, rate limits, challenges, and sign-in failures stop the guided scan. Cancellation does not close a dialog afterward or advance to the next list. Failed captures preserve the previous comparison.

The internal API reader remains covered by parser and pagination tests, including Instagram's separate deactivated-account records. It is not the primary-button capture path.

Both lists must finish and match their expected totals before a comparison is shown. Instagram can still withhold entries or rate limit a request; the checker stops rather than labeling missing accounts as non-mutuals. It never retries a rate limit or switches sources after one.

The corrected background reader still returned fewer unique accounts than the exact profile totals in an authenticated run. The new native-dialog flow passes virtualized browser fixtures but has not yet passed authenticated completeness acceptance. Native scrolling cannot guarantee that Instagram exposes every counted account. A complete Instagram data export can also be imported through the workspace app.

Exact text account IDs take precedence over rounded JSON numbers. Conflicting or unresolvable IDs stop the check. When the same account is renamed between Followers and Following, both rows use its latest observed name before comparison; IDs remain internal to the scan. Rows without IDs retain username-based matching.

Storage, permissions, endpoints, action engines, and export schemas are unchanged. Windows remains unsigned; macOS packages are ad-hoc signed and not notarized.
