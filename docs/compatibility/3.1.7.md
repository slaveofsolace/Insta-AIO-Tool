# 3.1.7 compatibility

Open your profile and select **Check Followers + Following**. Keep the profile open; neither list dialog needs to be opened or scrolled.

The checker reads exact totals from the profile header, including Instagram's hash-link counters and exact numeric tooltips. Hash links outside a matching profile header are ignored. The existing count request is used only when exact profile totals are unavailable.

Each continuation follows the cursor supplied by Instagram; the checker does not restart the list or guess missing pages. Temporary server failures can retry the same page within the existing attempt and time limits. Server-requested waits are respected; rate limits, challenges, and sign-in failures are not retried.

Instagram returns some follower records in `self_deactivated_followers.facepile`, separately from `users`. The checker includes those records, as Instagram's own list client does, and deduplicates them by account identity. Group labels and category counts are not account records and cannot fill a missing-data gap.

Both lists must finish and match their expected totals before a comparison is shown. Instagram can still withhold entries or rate limit a request; the checker stops rather than labeling missing accounts as non-mutuals. It never retries a rate limit or switches sources after one.

Earlier installed-build checks reached both terminal pages but did not reconcile with the profile totals. Subsequent inspection found that the parser ignored the separate deactivated-account records. Complete background comparisons remain unverified until the corrected reader passes an authenticated run. Waiting for DOM virtualization cannot repair an omitted response field. A complete Instagram data export can also be imported through the workspace app.

Exact text account IDs take precedence over rounded JSON numbers. Conflicting or unresolvable IDs stop the check. When the same account is renamed between Followers and Following, both rows use its latest observed name before comparison; IDs remain internal to the scan. Rows without IDs retain username-based matching.

Storage, permissions, endpoints, action engines, and export schemas are unchanged. Windows remains unsigned; macOS packages are ad-hoc signed and not notarized.
